# 전략 스킬 완료 알림

`/brand`, `/product`, `/competitor`, `/customer`, `/marketing-brief`, `/strategy-dashboard`가 요청받은 작업을 성공적으로 마치면 카카오톡 나에게 보내기, 지정된 슬랙 채널, 사용자 본인 이메일로 핵심 결과와 산출물 링크를 보낸다.

이 규칙은 사용자가 요청한 향후 완료 알림에 대한 상시 전송 지시다. 매번 별도 승인을 묻지 않으며 사용자가 전송을 생략하거나 수신처를 바꾸면 그 지시를 우선한다. 이번 스킬 수정 작업 자체는 여섯 스킬의 조사 산출물이 아니므로 알림 대상으로 삼지 않는다.

## 완료 기준과 순서

1. 실행한 스킬의 검증을 끝내고 요청 범위를 충족했는지 확인한다.
2. 산출물 변경이 있으면 [GitHub Push 절차](skill-output-git-push.md)에 따라 커밋과 push를 마치고 원격 커밋을 확인한다.
3. [공통 알림 스킬](../../.agents/skills/notify-results/SKILL.md)을 읽고 세 채널을 각각 실행한다.
4. 최종 답변에는 산출물, 원격 반영 결과와 채널별 전송 상태를 짧게 알린다.

실패, 중단, 승인 대기, 필수 검증 미완료나 push 실패 상태에는 성공 알림을 보내지 않는다. 원래 요청에 포함된 탐색이나 후보 추천만 완료한 경우 그 범위의 완료라고 명시하며 만들지 않은 문서나 수행하지 않은 상세 조사를 완료했다고 쓰지 않는다. 파일이 없는 결과는 확인된 후보 URL과 핵심 결과를 보낸다.

다른 스킬을 하위 절차로 실행했다면 최상위 작업에서 전체 결과를 한 번만 보낸다. 피드백으로 결과를 수정한 경우 새 실행 ID로 변경 내용을 알린다. 같은 실행 ID의 성공 채널은 재전송하지 않는다.

## 메시지와 산출물

- 제목에는 스킬명, 조사 대상과 완료한 범위를 쓴다.
- 본문에는 판단에 필요한 핵심 결과 2~3개와 중요한 미확인 사항을 간결하게 적는다.
- 산출물에는 실제 push한 커밋에 고정된 GitHub 파일 링크나 확인된 비공개 대시보드 주소를 붙인다.
- 산출물이 많으면 주요 문서와 폴더 또는 커밋 링크로 묶는다.
- 카카오톡은 200자 이내 본문과 산출물 보기 버튼, 슬랙은 Block Kit, 이메일은 짧은 HTML과 일반 텍스트로 보낸다.
- 슬랙 문장은 [슬랙 메시지 작성 기준](../../.agents/skills/natural-korean/references/slack-messages.md)을 따른다.

로컬 경로, 아직 push하지 않은 파일 주소, 만료되는 서명 URL이나 인증 정보가 포함된 링크를 보내지 않는다. 링크 전달을 첨부파일 전송이라고 보고하지 않는다. 알림을 위해 저장소나 사이트를 공개로 바꾸지 않는다.

## 인증과 장애 처리

카카오톡의 `KAKAO_ACCESS_TOKEN`은 `kapi.kakao.com`으로만, 슬랙의 `SLACK_WEBHOOK_PATH`는 `hooks.slack.com`으로만 전달하도록 HTTP 시크릿으로 바인딩한다. 현재 환경의 `KAKAO`, `SLACK` 이름은 같은 용도의 기존 바인딩으로만 사용할 수 있으며 실제 비밀값을 읽거나 복사해 새 키를 만들지 않는다.

HTTP 시크릿과 URL 경로 치환은 실행 전 환경 도구의 최신 readiness로 확인한다. 슬랙 경로 치환을 지원하지 않으면 환경 설정에서 올바른 바인딩이 필요하다고 보고하며 시크릿을 파일이나 로그로 꺼내 우회하지 않는다. SenderKit 인증은 연결된 플러그인이 관리하며 별도 API 키나 Resend로 대체하지 않는다.

각 채널은 독립 실행한다. 한 채널이 실패해도 나머지는 시도하고 산출물과 push 결과를 보존한다. HTTP 응답 본문, 요청 헤더, 전체 웹훅 URL과 예외 원문을 출력하지 않는다. 토큰 만료나 권한 부족은 상태 코드와 필요한 설정만 보고한다. 카카오 토큰을 임의로 갱신하거나 다른 수신자에게 보내지 않는다.

타임아웃 등 수락 여부가 불명확하면 `확인 불가`로 남기고 무조건 재시도하지 않는다. 이메일 재시도에는 같은 idempotency key를 쓰고 메시지 ID로 상태를 확인한다. API 수락, 큐 등록과 최종 배달은 구분하며 실제 확인한 수준까지만 보고한다.
