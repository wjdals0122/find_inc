# 결정: 버추얼 오피스 5F 대강당과 AI 품평회

- 날짜: 2026-11-18
- 요청: 버추얼 오피스에 발표·품평용 대강당을 만들고, 마케팅 브리핑과 광고 이미지·영상을 화면에 띄워 여러 관점의 Codex 에이전트가 차례로 피드백하는 품평회를 연다. 대표가 채팅으로 참여하고, `세션 종료` 시 발표와 피드백을 `docs/`에 정리한다.
- 결정:
  - 오피스 최상층에 5F 대강당을 추가했다. 요약 단면에는 무대·대형 화면·커튼·앞줄 객석이 있고, 상세 평면에는 객석 45석·로비·컨트롤 부스·대기실이 있다.
  - 5F에 처음 들어가면 설정 팝업이 열린다. 발표 주제, 산출물, 평가 에이전트 수(1~6), 발표자와 평가자별 관점·모델·Effort를 고른다. 진행 중인 품평회가 있으면 같은 팝업에서 기존 세션을 보여주고 `이어서 보기`로 돌아간다. 무대 왼쪽 `AI 품평회` 버튼으로 다시 열 수 있다.
  - 산출물 경로: 요청서의 `01-contents/marketing-brief/`는 저장소에 없다. marketing-brief 스킬의 실제 저장 경로인 `01-strategy/brief/<브랜드>/<상품>/`을 기본으로 쓰고, 두 후보 경로(`01-contents/marketing-brief`, `01-strategy/marketing-brief`)도 함께 찾는다. `02-contents/`는 `.gitignore` 대상인 Google Drive 동기화 폴더라 Git에 없다. 그래서 실행 PC의 로컬 폴더(`ad-images`, `ad-videos`의 `ads-*`)를 쓴다.
  - 저장소가 비공개라 브라우저가 GitHub를 읽을 수 없다. 목록은 Happier 데몬의 기기 RPC `daemon.filesystem.listDirectory`로 실행 PC에서 직접 읽는다. 화면 표시는 발표자 세션의 `readFile` RPC로 가져온다(2.5MB 제한). 큰 파일은 화면 대신 안내 문구를 띄운다. 발표자는 `git fetch` 후 원격이 더 최신이면 `git show`로 읽고, 작업 트리는 바꾸지 않는다.
  - 에이전트마다 별도 Codex 세션을 만들어 선택한 모델과 Effort를 그대로 적용한다. 순서는 발표자 발표 → 평가자 1…N 피드백(각자 앞선 기록을 받음) → 발표자 답변 → 자유 토론이다. 다음 순서는 브라우저가 상태를 조회할 때 진행되므로, 품평회 창을 닫으면 진행이 멈췄다가 다시 열면 이어진다.
  - 말풍선과 채팅에는 세션의 `@@발표:`, `@@피드백:` 형식 줄과 대표 발언만 표시한다. 대표 채팅은 지금 말하는 세션(평가 중이면 해당 평가자, 그 외에는 발표자)의 pending 큐로 암호화해 보내고, 이후 평가자 프롬프트에도 포함한다.
  - `세션 종료` 시 발표자가 `docs/reviews/YYYY-MM-DD-<주제>.md`에 주제·참석 에이전트(관점·모델·Effort)·산출물·발표 요약·관점별 피드백·대표 의견·답변·개선 사항을 정리한다. 커밋과 push는 하지 않는다.
- 검증: `dashboard/tests/ai-review.cjs`(프리뷰 샘플 전송) 통과. Happier 클라이언트 단위 테스트 15개 통과(품평 순서, 채팅 대상, 종료 요청, 기기 RPC 목록, 프로젝트 밖 경로 거부 포함). 5층 구성에 맞춰 `office-design.cjs`를 고쳤고 `virtual-office.cjs`, `ai-meeting.cjs`, `auth.cjs`와 함께 통과했다. Computer Use는 사용하지 않았다.
- 제한: 실제 Happier/Codex 세션으로 품평회를 실행해 보지 않았다. `daemon.filesystem.listDirectory`와 세션 `readFile`은 로컬 Happier CLI 0.2.21 구현을 근거로 했다. 세션 메시지는 최근 100개 기준이다.
