# 대시보드 테스트 케이스

대상: `01-strategy/dashboard/dashboard.html`

각 항목은 **확인 동작 → 기대 결과** 순서다. 실제로 확인한 항목만 체크하고, 실패한 항목은 아래 실행 기록에 남긴다. 이 문서의 체크박스는 테스트 실행 결과가 아닌 실행용 목록이다.

## 테스트 준비

- 로컬 서버를 실행하고 `http://127.0.0.1:8765/01-strategy/dashboard/dashboard.html`에 접속한다. 포트가 다르면 실행 중인 서버 주소를 사용한다.
- Firebase Authentication에 등록된 테스트 계정과 올바른 비밀번호를 준비한다. 프로젝트 관리용 Google 로그인과 웹 앱 계정은 별개다.
- 실패 테스트에는 존재하지 않는 테스트 이메일과 잘못된 비밀번호를 사용한다. 실제 계정 정보와 비밀번호는 이 문서에 적지 않는다.
- 최초 접속 테스트는 시크릿 창이나 로그아웃 상태에서 진행한다. 로그인 유지 테스트는 일반 창에서 진행한다.
- 화면 크기는 브라우저의 페이지 확대율 100%에서 아래 조합으로 확인한다. 가능하면 모바일 실기기에서도 확인한다.

| 구분 | 화면 크기 예시 | 확인할 화면 |
| --- | --- | --- |
| 데스크톱 | 1440 × 1000 | 로그인, 대시보드, 검색, 원문 보기 |
| 태블릿·작은 노트북 | 1024 × 768, 820 × 1180 | 로그인, 상단바, 메뉴, 보고서 |
| 모바일 | 390 × 844 | 로그인, 상단바, 메뉴, 보고서, 팝업 |
| 작은 모바일 | 320 × 568 | 폼, 오류 안내, 로그아웃, 가로 넘침 |

## 1. UI와 브랜드 로고

- [ ] **UI-01 · 기본 배치** — 로그인 화면과 대시보드를 각각 연다 → 제목·본문·입력창·버튼이 겹치거나 잘리지 않는다.
- [ ] **UI-02 · 글자와 아이콘** — 한글·영문·아이콘을 확인한다 → 글자가 깨지지 않고 버튼의 의미를 알아볼 수 있다.
- [ ] **UI-03 · 브랜드 이미지** — 데스크톱 로그인 화면을 연다 → BMW·LG전자·토스·카카오·신한 로고 5개가 깨진 이미지 없이 표시된다.
- [ ] **UI-04 · 로고 애니메이션** — 로고 움직임을 지켜본다 → 로고가 원형 궤도를 따라 이동하며, 회전 중에도 로고 자체는 바르게 보이고 중앙 문구를 가리지 않는다.
- [ ] **UI-05 · 라이트·다크모드** — 대시보드 테마를 바꾸고 로그아웃한다 → 두 테마에서 대시보드와 로그인 화면의 글자·입력값·오류 안내를 읽을 수 있다.
- [ ] **UI-06 · 동작 줄이기** — 운영체제나 브라우저의 동작 줄이기를 켠다 → 로고 애니메이션이 멈추고 로고가 한곳에 겹치지 않는다.

## 2. 작은 화면과 반응형

- [ ] **RESP-01 · 로그인 폼** — 표의 각 화면 크기로 접속한다 → 이메일·비밀번호·로그인 버튼과 오류 안내가 화면 안에 표시되고 의도하지 않은 가로 스크롤이 없다.
- [ ] **RESP-02 · 모바일 로그인 구성** — 화면 폭을 390px와 320px로 줄인다 → 로고 애니메이션 영역이 접히고 로그인 폼이 표시된다.
- [ ] **RESP-03 · 낮은 화면 높이** — 320 × 568 화면에서 폼을 사용한다 → 필요한 경우 세로로 스크롤해 로그인 버튼과 안내 문구까지 접근할 수 있다.
- [ ] **RESP-04 · 상단바** — 로그인 후 작은 화면에서 확인한다 → 브랜드명·검색·테마·로그아웃·메뉴 버튼이 겹치지 않고 누를 수 있다. 로그아웃이 아이콘으로 표시되어도 기능을 식별할 수 있다.
- [ ] **RESP-05 · 보고서와 표** — 상품 정보·경쟁사 비교·고객 분석·브리프를 연다 → 카드와 본문이 잘리지 않고, 넓은 표는 해당 영역에서 스크롤해 모든 열을 볼 수 있다.
- [ ] **RESP-06 · 팝업** — 모바일에서 검색·원문·이미지 팝업을 연다 → 내용과 닫기 버튼이 화면 안에 있고 필요한 내용을 스크롤해 볼 수 있다.
- [ ] **RESP-07 · 화면 전환** — 로그인 전후에 창 크기를 바꾸거나 기기를 회전한다 → 레이아웃이 새 크기에 맞춰지고 입력값·로그인 상태·현재 보고서가 유지된다.

## 3. 로그인 화면 열기와 입력

- [ ] **LOGIN-01 · 최초 접속** — 로그아웃 상태로 주소를 연다 → 로그인 화면이 열리고 대시보드 내용이 잠깐 노출되지 않는다.
- [ ] **LOGIN-02 · 보고서 주소 직접 접속** — 로그아웃 상태에서 특정 보고서 주소를 연다 → 바로 보고서가 열리지 않고 로그인 화면이 표시된다.
- [ ] **LOGIN-03 · 로그인 준비** — 페이지 로딩 직후와 연결 완료 후를 확인한다 → 준비 중에는 로그인 버튼이 비활성화되고, 연결 완료 후 사용할 수 있다.
- [ ] **LOGIN-04 · 빈 값** — 이메일이나 비밀번호를 비운 채 로그인한다 → 필수 입력 안내가 표시되고 대시보드는 열리지 않는다.
- [ ] **LOGIN-05 · 이메일 형식** — 이메일에 `invalid-email`을 입력하고 로그인한다 → 이메일 형식 안내가 표시된다.
- [ ] **LOGIN-06 · 비밀번호 표시** — 비밀번호를 입력하고 눈 아이콘을 두 번 누른다 → 표시·숨김이 전환되고 입력값은 유지된다. 아이콘의 접근성 이름도 상태에 맞게 바뀐다.
- [ ] **LOGIN-07 · 키보드 조작** — Tab으로 입력창과 버튼을 이동하고 비밀번호 입력 후 Enter를 누른다 → 포커스가 보이고 로그인 버튼을 누른 것과 동일하게 동작한다.

## 4. 로그인 성공과 상태 유지

- [ ] **AUTH-01 · 정상 로그인** — 등록된 테스트 계정과 올바른 비밀번호로 로그인한다 → 로그인 화면이 닫히고 기존 대시보드가 표시된다.
- [ ] **AUTH-02 · 로그인 처리 중** — 로그인 버튼을 누른 직후 다시 누른다 → 처리 중 안내가 표시되고 중복 제출되지 않는다.
- [ ] **AUTH-03 · 원래 보고서 복원** — 특정 보고서 주소에서 로그인한다 → 주소에 해당하는 브랜드·상품·보고서가 열린다.
- [ ] **AUTH-04 · 새로고침** — 로그인한 탭에서 새로고침한다 → 로그인 상태 확인 후 대시보드가 다시 표시된다.
- [ ] **AUTH-05 · 로그인 유지 선택** — 로그인 상태 유지를 체크하고 로그인한 뒤 같은 주소를 새 탭에서 연다 → 같은 브라우저의 새 탭에서도 대시보드가 열린다.
- [ ] **AUTH-06 · 브라우저 재실행** — 로그인 상태 유지를 체크한 상태로 브라우저를 완전히 종료하고 다시 연다 → 브라우저가 사이트 데이터를 삭제하지 않는 설정이면 로그인 상태가 복원된다.
- [ ] **AUTH-07 · 로그인 유지 해제** — 로그아웃 후 체크를 해제하고 로그인한다. 로그인된 탭을 모두 닫고 주소를 새로 입력해 연다 → 로그인 화면이 표시된다. 닫은 탭 복원 기능은 사용하지 않는다.

## 5. 로그인 실패와 연결 오류

- [ ] **ERROR-01 · 잘못된 비밀번호** — 등록된 테스트 이메일에 틀린 비밀번호를 입력한다 → 이메일 또는 비밀번호 확인 안내가 표시되고 대시보드는 열리지 않는다.
- [ ] **ERROR-02 · 없는 계정** — 등록되지 않은 테스트 이메일로 로그인한다 → 계정의 존재 여부를 구체적으로 노출하지 않는 오류 안내가 표시되고 대시보드는 열리지 않는다.
- [ ] **ERROR-03 · 실패 후 재시도** — 로그인 실패 후 올바른 계정 정보를 입력한다 → 버튼을 다시 사용할 수 있고 로그인에 성공한다.
- [ ] **ERROR-04 · 로그인 요청 중 연결 끊김** — 요청 직전에 브라우저를 오프라인으로 전환한다 → 연결 오류 안내가 표시되고 로그인 화면에 남는다. 연결 복구 후 다시 시도할 수 있다.
- [ ] **ERROR-05 · SDK 로딩 실패** — 브라우저 개발자 도구에서 Firebase SDK 요청을 차단한 뒤 새로고침한다 → 연결 실패와 다시 연결하기 버튼이 표시되고 대시보드는 열리지 않는다. 차단 해제 후 다시 연결하기를 누르면 정상 화면으로 복구된다.

## 6. 비밀번호 재설정

실제 메일 발송을 확인할 때는 수신 가능한 테스트 계정을 사용한다.

- [ ] **RESET-01 · 이메일 누락·형식 오류** — 이메일을 비우거나 형식에 맞지 않게 입력하고 비밀번호 재설정을 누른다 → 입력 안내가 표시되고 메일 요청이 진행되지 않는다.
- [ ] **RESET-02 · 재설정 메일** — 등록된 테스트 이메일로 재설정을 요청한다 → 화면에 안내가 표시되고 수신한 링크로 비밀번호를 변경할 수 있다. 변경한 비밀번호로 로그인된다.
- [ ] **RESET-03 · 없는 계정 안내** — 등록되지 않은 테스트 이메일로 요청한다 → 계정 존재 여부가 드러나지 않는 안내가 표시된다.
- [ ] **RESET-04 · 연속 요청** — 요청 성공 직후 다시 누른다 → 잠시 후 다시 요청하라는 안내가 표시되어 즉시 재발송되지 않는다.

## 7. 로그아웃과 접근 상태

- [ ] **LOGOUT-01 · 기본 로그아웃** — 대시보드 상단바의 로그아웃을 누른다 → 로그인 화면으로 돌아가고 보고서가 보이지 않는다.
- [ ] **LOGOUT-02 · 새로고침·뒤로 가기** — 로그아웃 후 새로고침하거나 뒤로 가기·앞으로 가기를 한다 → 로그아웃 전 보고서 화면을 그대로 사용할 수 없으며 로그인 화면이 표시된다.
- [ ] **LOGOUT-03 · 다른 탭 동기화** — 로그인 유지로 대시보드를 두 탭에서 열고 한 탭에서 로그아웃한다 → 다른 탭도 로그인 화면으로 돌아간다.
- [ ] **LOGOUT-04 · 열린 팝업·미디어 정리** — 팝업을 열거나 재생 가능한 오디오·영상을 재생한 상태에서 로그아웃한다. 필요하면 다른 로그인 탭에서 로그아웃한다 → 팝업이 닫히고 재생이 멈춘다.
- [ ] **LOGOUT-05 · 로그아웃 후 재로그인** — 로그아웃한 화면에서 정상 계정으로 다시 로그인한다 → 대시보드와 상단바 기능을 다시 사용할 수 있다.

## 8. 기존 대시보드 기능

- [ ] **DASH-01 · 브랜드·상품 전환** — 로그인 후 브랜드와 상품을 바꾼다 → 제목·이미지·본문·선택 상태가 해당 항목에 맞게 바뀐다.
- [ ] **DASH-02 · 보고서 메뉴** — 상품 정보·경쟁사 비교·고객 분석·메시지와 브리프를 차례로 연다 → 선택한 내용이 표시되고 활성 메뉴 표시가 맞는다.
- [ ] **DASH-03 · 검색** — 검색 버튼 또는 검색 단축키로 문서를 찾고 결과를 선택한다 → 검색 팝업이 열리고 선택한 결과에 맞는 자료로 이동한다.
- [ ] **DASH-04 · 원문 보기·다운로드** — 원문 보기를 열어 문서를 전환하고 다운로드한다 → 해당 문서의 원문이 표시되고 올바른 파일이 내려받아진다.
- [ ] **DASH-05 · 이미지 보기** — 보고서 이미지를 눌러 확대하고 닫는다 → 올바른 이미지가 열리며 팝업을 닫으면 보고서를 계속 사용할 수 있다.
- [ ] **DASH-06 · 메시지 선택·복사** — 브리프의 메시지를 바꾸고 복사한다 → 선택한 메시지와 관련 내용이 표시되고 복사된 문구가 일치한다.
- [ ] **DASH-07 · 실행 오류** — 로그인부터 보고서 전환·로그아웃까지 브라우저 콘솔을 확인한다 → 처리되지 않은 JavaScript 오류가 없다.

## 자동 검증과 확인 범위

- 기존 자동 검증: [`01-strategy/dashboard/tests/auth.cjs`](../../01-strategy/dashboard/tests/auth.cjs). 실행 방법은 [로그인 안내](../../01-strategy/dashboard/AUTH.md)의 검증 절을 따른다.
- 기본 자동 검증은 인증 응답을 가로채 화면 동작을 확인한다. 실제 계정 로그인·메일 수신·브라우저 재실행·실기기 확인은 별도로 수행한다.
- 이 목록은 로그인에 따른 화면 전환과 대시보드 기능을 검증한다. 내장 보고서 원본의 비공개 보호 여부는 [구현 범위](../../01-strategy/dashboard/AUTH.md#구현-범위)를 참고한다.
