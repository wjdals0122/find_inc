# ChatGPT Sites 소유자 전용 배포

Sites 배포를 요청받았을 때만 읽는다. 도구와 헬퍼의 최신 사용법은 현재 설치된 `sites:sites` 스킬을 따른다. 아래 절차는 원본 리포트 보존과 접근 범위 확인에 관한 보완 지침이다. 특정 상품명, 계정, 프로젝트 ID나 플러그인 버전을 재사용하지 않는다.

## 원본과 사이트 연결

1. 배포할 `01-strategy/dashboard/dashboard.html`을 확인한다. 별도 사이트 작업 폴더의 `dist/index.html`에 그대로 복사하고 SHA-256으로 동일성을 확인한다. 기존 보고서와 다른 상품 데이터를 수정하거나 새 프레임워크로 재작성하지 않는다. 상대 경로 에셋이 있다면 해당 경로로 함께 포함한다.
2. 요청한 기존 사이트나 선택한 작업 폴더의 `.openai/hosting.json`에 프로젝트 ID가 있으면 그 사이트를 사용한다. 연결 정보가 없고 새 사이트 요청이면 한 번만 생성하고 반환 ID를 즉시 기록한다. 실패나 자격 증명 만료를 이유로 사이트를 다시 만들지 않는다.
3. 설치된 Sites 플러그인의 `set-project-id.mjs`로 ID와 정적 디렉터리 `dist`를 기록한다. 기존 사이트를 수정할 때는 먼저 Sites 워크플로로 실제 원격 소스를 열어 기존 변경을 보존한다.

## 소유자만 접근하는지 확인

업로드·배포 전에 `get_site`로 현재 사용자가 소유자인지, 허용 사용자가 소유자 한 명인지 확인한다. 제공되는 정책 필드에서 그룹·워크스페이스 공유, 다른 편집자와 외부 방문자 허용도 확인한다. `access_mode: custom` 또는 로그인 필요라는 표시만으로 소유자 전용이라고 판단하지 않는다.

정책을 확인할 수 없거나 공유 대상이 남아 있으면 의도한 접근 범위를 확정할 때까지 배포하지 않는다. 접근 권한 변경은 사용자가 요청한 범위에서 지원 도구로만 수행한다. 외부 공개나 인증을 우회하는 URL을 대안으로 만들지 않는다.

## 소스 전송과 비공개 배포

- 현재 Sites 스킬의 `site-workflow.mjs`를 사용해 소스 커밋·푸시와 아카이브를 준비한다. 빌드 없는 HTML이면 불필요한 설치·빌드 명령 없이 처리한다. 아카이브는 체크아웃 밖의 절대 경로에 둔다.
- 반환된 소스 자격 증명은 헬퍼의 숨김 표준입력으로 전달한다. 토큰을 명령 인자, 저장 파일, 출력이나 최종 URL에 넣지 않는다. 자격 증명이 없으면 같은 프로젝트의 자격 증명을 복구한다.
- 헬퍼가 반환한 `project_id`, `commit_sha`, `archive`로 `save_version_and_deploy_private`를 호출한다. 결합 도구가 없으면 버전 저장 후 소유자 전용 배포 도구를 사용한다. 일반·공개 배포 도구로 자동 대체하지 않는다.
- 이미 사용자에게 비공개 배포를 요청받았다면 같은 작업에 대화상 확인을 반복하지 않고 도구의 승인 절차를 따른다. 이 스킬 수정 요청 자체는 재배포 허가가 아니다.
- 결과가 진행 중이면 반환된 배포 ID로 상태를 확인한다. 저장된 버전이 남은 부분 실패는 해당 버전에서 재시도해 중복 저장을 피한다. 소유자 전용 조건 불일치 오류는 정책을 다시 읽고 해결 전 배포를 멈춘다.

## 실제 발생한 전송 오류의 처리

- 샌드박스 네트워크 제한이면 허용된 실행 승인 경로로 같은 프로젝트에서 재시도한다.
- Git 메타데이터 오류는 읽기 전용 Git 명령으로 원인을 먼저 확인한다. Windows 실행 계정 차이로 `dubious ownership`이 확인된 경우에만 정확한 체크아웃 경로에 명령 범위의 `safe.directory`를 적용한다. 기존 `GIT_CONFIG_*` 설정은 보존한다. 전역 와일드카드 허용이나 `.git` 삭제로 우회하지 않는다.
- 같은 원인이 해결되지 않으면 중단하고 차단된 단계와 필요한 조치를 알린다. 사이트를 새로 만들거나 공개 설정으로 바꾸는 재시도를 하지 않는다.

## 완료 확인과 전달

배포 성공 후 `get_site`로 소유자 전용 정책을 다시 확인하고 실제 배포 URL을 대조한다. 원본 HTML과 배포용 사본의 동일성도 확인한다. 배포 성공과 화면 기능 검증은 구분해서 보고한다.

최종 답변은 접근 범위 확인 결과와 실제 성공 응답의 웹 주소를 간단히 전달한다. 예상 주소를 배포 완료 주소처럼 쓰지 않는다. 사용자가 요청한 경우 URL을 코드블록에 넣고, 자격 증명과 계정 식별자는 노출하지 않는다.
