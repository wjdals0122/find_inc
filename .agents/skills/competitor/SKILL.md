# Competitor

자사 상품의 구매자가 고려할 경쟁 상품과 대체재를 찾고 근거에 기반해 비교한다. 실물 상품, 소프트웨어와 서비스에 적용한다. 사용자가 요청한 탐색·조사·비교·수정 단계만 수행한다.

## 범위와 기존 자료

- 대화와 `rg`로 자사 브랜드·상품·모델/버전·시장·대상 고객, 지정 경로, 기존 경쟁 후보, 조사 범위와 예산을 확인한다. 기존 자사 `product.md`, 관련 수집 기록과 기존 `competitor.md`를 읽고 대상과 확인일을 파악한다. 사용자가 문서를 수정했다고 하면 현재 파일을 다시 읽는다.
- 자사 상품의 강점·사용 조건·고객이 해결하려는 문제를 비교 기준으로 삼는다. 모델·세대·연식·지역이 다른 자료는 구분하고, 대상이나 조건이 바뀌면 기존 후보와 근거가 여전히 유효한지 재확인한다. 빈 템플릿 자리표시자가 남았더라도 문맥에 이미 선택된 후보가 있으면 이를 명시하고 사용한다. 식별이 불가능하면 가능한 독립 작업을 진행하며 필요한 정보만 묻는다.
- 후보 추천만 요청하면 가격대·용도·주요 기능이 비슷한 직접 경쟁 상품을 고르고, 요청받은 경우 같은 고객 문제를 다른 방식으로 해결하는 대체재를 별도 제시한다. 사용자가 지정한 수와 대상을 우선한다. 모델·공식 페이지·추천 이유를 간단히 제시하고, 가격 또는 구성의 유사성이 확인되지 않았으면 한계를 밝힌다. 후보 추천과 후보 선정 완료를 혼동하지 않는다.
- 사이트 탐색만 요청하거나 아직 수집하지 말라고 하면, 선정된 상품의 주소와 대상 일치 여부를 확인하는 최소 검색만 한다. 사이트별 직접 주소·조사 항목·접근 상태를 제시하고 본문 추출, 후기·영상 분석, 파일 저장과 상세 비교는 시작하지 않는다. 직접 상품 페이지를 찾지 못한 검색 주소는 검색 진입점으로 표시한다.
- 조사·비교가 요청되면 이미 주어진 범위와 예산으로 진행한다. 후보 선택 또는 수집을 위한 불필요한 승인 단계를 추가하지 않는다. 사용자가 선택한 경쟁 상품만 상세 조사하고, 추천만 했던 대체재는 요청 범위에 포함됐을 때 조사한다.

## 조사와 근거

- 자사 상품과 경쟁 상품 모두에 [product](../product/SKILL.md)의 상품 식별·조사 항목과 [crawler](../crawler/SKILL.md)의 수집·예산·기록 절차를 적용한다. 실제 수집 전에 두 스킬을 읽고, 없으면 사용 가능한 무료 자료로 계속하며 누락된 도구나 절차를 알린다. 기존 자료는 대상·날짜를 확인해 재사용하고 필요한 시의성 있는 부분을 갱신한다.
- 공식 상품·가격표·설명서·약관을 우선하고, 자사 조사에 쓰인 적절한 사이트도 참고한다. 실물 상품은 **다나와와 네이버 쇼핑**을 확인한다. 차량 등은 전문 카테고리를 추가하고 용품·중고·리스와 해당 신상품을 구분한다. 소프트웨어·서비스는 공식 요금·약관과 관련 판매 채널을 사용한다. 접근 제한, 미수집, 해당 없음은 구분한다.
- 웹 검색 및 Bright Data, 부족한 채널의 Apify, 영상의 watch Gemini, 이미지와 PDF 판독은 crawler 지침과 승인된 예산을 따른다. 무료 실행만 승인된 경우 그대로 유지한다. 검색 스니펫, 빈 응답, 영상 제목이나 실행 성공만으로 본문·영상 수집 완료를 주장하지 않는다.
- 후기의 모델·연식·시장·사용 기간·옵션·환경과 차주/전문가/협찬 여부를 적는다. 실제 운전·사용, 정차 체험과 단순 반응을 나눈다. 개별 사례를 결함률이나 장기 내구성으로 일반화하지 않는다. 댓글·답글은 원글과 직접 부모의 식별자를 보존한다.

## 비교와 판단

- 가능한 한 같은 시장·통화·시점, 고객 용도, 등급·옵션·구성으로 맞춘다. 맞출 수 없는 세대·연식·구동 방식·시험 규격·옵션·국가 차이는 표에 명시하고, 단위나 기준이 다른 수치로 순위를 만들지 않는다. 국내 미출시 또는 미확정 가격은 미확인으로 두고 해외 가격, 환산 보도와 조건부 추정을 구별한다.
- 가격은 상품·모델·버전·옵션, 정가/실거래가/할인/리스, 통화·세금·배송·설치·확인일과 출처를 함께 적는다. 옵션·구독료·소모품·충전/운영·보험·금융·해지 비용은 상품에 해당하는 것만 별도로 표시한다. 무료 기간, 갱신·해지·환불과 지역 제한을 확인한다. 빠진 비용이 있으면 총액·총소유비를 확정하거나 절감액을 추정하지 않는다.
- 요청된 가격·기능·사용 조건·후기를 빠짐없이 비교한다. 보증의 기간뿐 아니라 범위·제외 조건과 일반 브랜드 안내인지 해당 모델 계약인지 구분한다. 각 상품의 우위와 약점은 동일 조건의 근거와 한계를 제시하고, 기능이나 경험에서 이어지는 고객 이점과 적합한 고객을 설명한다. 근거가 부족하면 우열 미확인으로 둔다.
- 원문·짧은 발췌·요약·판단을 구분하고 주장 가까이에 직접 출처와 확인 날짜를 둔다. 재사용한 자료의 원래 수집 시간은 보존한다. 게시일·확인일과 기록 작성일이 다르면 따로 적는다.

## 문서 작성과 수정

- 사용자가 지정한 경로가 우선이다. 기본 결과는 `01-strategy/competitor/<자사 브랜드명>/<자사 상품명>/competitor.md`에 둔다. 브랜드와 상품 폴더를 분리하며 기존 구조와 사용자 파일을 존중한다. 자사 `product.md`는 비교 근거로 읽고 명시적 수정 요청 없이 덮어쓰지 않는다.
- 문서에는 조사 범위·상품 식별, 비교 기준, 가격과 추가 비용, 기능, 사용 조건, 실제 후기, 차별점과 추천 고객, 출처·확인일, 미확인·실패를 담는다. 상품 유형과 요청에 따라 구조를 조정한다. crawler 기록 형식을 따라 원문 또는 허용된 발췌·출처·시각·도구·누락·비용을 같은 결과 폴더에 연결한다. 출처 전문 재배포가 제한되면 링크와 짧은 발췌·미보존 사유를 남긴다.
- 수정 요청 시 현재 문서와 관련 기록을 먼저 읽고 사용자 편집을 보존한다. 모델·세대·시장·가격 기준이 바뀌면 표, 가격 계산, 후기, 차별점, 추천 고객과 출처를 함께 재대조한다. 새로 확인한 내용의 날짜만 갱신하고 기존 수집 시각은 유지한다. 기존 파일이나 에셋을 임의 삭제하지 않는다. 상태 질문에는 짧게 답하고 승인된 작업을 계속한다.
- 사용자가 병렬 작업을 요청했거나 `team-lead`를 명시한 경우 [team-lead](../team-lead/SKILL.md)를 읽고 상품·후기 등 독립 범위를 나눈다. 각 결과의 원문과 조건을 검토한 뒤 합친다. 이 스킬 자체는 자동 위임을 요구하지 않는다.

## 완료 확인

결과가 요청된 단계·대상·항목을 충족하는지, 링크와 로컬 기록이 연결되는지, 가격 조건·출처·날짜·후기 유형·미확인과 비용이 명시됐는지 확인한다. 최종 응답에는 결과 경로 또는 후보, 중요한 비교 한계와 실패, 수집·재사용 현황 및 비용을 간결하게 알린다.

## 산출물 생성 후 GitHub Push

산출물을 새로 만들거나 수정하고 검증을 마치면 [산출물 GitHub Push 절차](../../../docs/guides/skill-output-git-push.md)를 읽고 따른다. 이번 작업의 산출물과 필요한 관련 파일만 커밋한 뒤 GitHub 작업 브랜치로 push하고, 원격 반영을 확인한 후 완료를 보고한다. 별도 push 승인을 반복해서 묻지 않는다. 파일 변경이 없는 탐색·제안만 수행했다면 빈 커밋을 만들지 않는다.
