# Marketing Brief

조사 근거를 고객의 구매 이유와 한 줄 메시지로 연결하고 제작자가 실행할 수 있는 마케팅 브리프로 구체화한다. 실물 상품, 소프트웨어, 구독과 서비스에 적용한다. 메시지 제안, 브리프 작성, 수정 중 요청받은 범위를 수행한다.

## 입력과 범위

- 대화와 `rg`로 브랜드명, 상품명, 모델·버전·시장, 목표 고객, 요청한 메시지 수, 채널, 행동 목표와 저장 위치를 확인한다. 기존 `marketing_messages.md`, `brief.md`, `brand.md`, `product.md`, `competitor.md`, `customer.md`와 필요한 원문·에셋 기록을 찾는다. 브랜드와 상품 폴더를 구분하며 사용자가 수정한 파일은 현재 내용을 다시 읽는다.
- 기존 조사로 기획을 요청받으면 그 자료를 재사용한다. 필요한 자료가 없거나 확인일이 오래됐으면 한계를 적고 가능한 기획을 완성한다. 신규 조사나 시의성 있는 사실 확인이 필요한 경우 관련 범위만 확인하며, 본격적인 수집은 사용자가 허용한 범위와 예산 안에서 [crawler](../crawler/SKILL.md)를 따른다.
- 상품과 고객의 사실, 조사자의 가설, 이번 기획 제안을 구분한다. 구매자의 나이·소득·가족 구성이나 행동을 원문 없이 만들어 내지 않는다. 채널 선택과 핵심 고객은 근거가 확인된 범위까지만 확정하고 나머지는 기획 가설로 표시한다.
- 메시지만 요청하면 메시지 제안까지, 앞서 만든 메시지의 구체화를 요청하면 해당 문구와 구매 이유를 유지하며 브리프로 확장한다. 콘텐츠 제작·게시·광고 집행은 별도 요청 범위다.

## 메시지 제안

- 사용자 지정 수만큼 각각 **핵심 고객, 강조할 구매 이유, 근거, 메시지 한 줄**을 작성한다. 수가 없으면 근거가 있는 주요 구매 이유에 맞춰 제안하고 불필요한 후보로 채우지 않는다.
- 서로 다른 표현으로 같은 장점을 반복하지 않는다. 각 메시지가 해결하는 고객 문제나 원하는 결과를 대조해 구매 이유가 실제로 다른지 확인한다. 기능·사용 경험·구매 조건 등 어떤 이유를 택할지는 해당 상품의 근거에 맞춘다.
- 고객의 문제에서 제품의 기능이나 특성, 고객이 얻을 이점으로 이어지는 논리를 설명한다. 제품에 있다는 기능을 모든 고객이 원하는 이유로 단정하지 않고 고객 원문이나 분석을 연결한다. 가설은 가설로 남긴다.
- 구매 이유 옆에 직접 출처와 확인 날짜를 적고 모델·옵션·지역·버전·시험 조건을 보존한다. 공식 제원, 실제 사용, 전문가 시승과 판매자 의견을 구분한다. 단기 평가를 장기 신뢰성으로, 경쟁차 불만을 자사 품질 우위로 바꾸지 않는다.
- 한 줄 문구에도 근거의 적용 범위가 유지되어야 한다. 특정 모델 전용 기능을 전 제품의 장점처럼 쓰지 않고 가격·절감액·성능·안전·편의 보장은 확인한 수준을 넘지 않는다. 필요한 조건을 각주로만 숨겨 과장된 본문을 정당화하지 않는다.

## 채널별 브리프

메시지마다 다음 내용을 구체화한다. 기존 문구를 바꿔 달라는 요청이 없다면 메시지와 핵심 근거를 유지한다.

1. **활용 방향:** 핵심 고객과 구매 이유에 맞는 채널, 형식, 유도할 행동을 제안한다. 모든 메시지에 같은 채널을 기계적으로 적용하지 않는다. 채널·형식·분량은 기획 제안으로 표시하고, 영상 길이나 카드 수를 모든 상품의 고정 규칙으로 만들지 않는다.
2. **콘텐츠 구성:** 고객의 불편 또는 고민 → 제품이 해결하는 포인트 → 근거와 제품 설명 → CTA 순서로 구성한다. 영상은 구간별 장면·자막, 카드뉴스는 카드별 내용, 글과 랜딩 페이지는 절별 내용을 적는다. 제품이 실제로 해결하지 못하는 불편은 해결한다고 쓰지 않는다.
3. **CTA:** 버튼·링크 문구와 연결할 목적지, 도착 후 할 일을 지정한다. CTA는 고객에게 원하는 행동을 요청하는 문구다. 실제 상품의 판매·예약·제공 지역·계약 상태를 확인하고, 미확정이면 모델 안내나 제공 조건 확인 등 실행 가능한 행동을 제안한다. 게시물 형식에 클릭 가능한 링크가 없는 경우 프로필·스토리 등 실제 연결 방법을 적는다. 미확인 주소를 작동하는 링크로 만들지 않는다.
4. **제작 가이드:** 문체, 컬러, 서체, 로고, 슬로건과 피할 표현을 브랜드 가이드와 연결한다. 필요한 이미지·영상·화면 시연을 지정하고 보유 자료와 추가 확보할 자료를 구분한다. 제작자가 어떤 정보를 보여 줘야 하는지 알 수 있도록 근거와 조건을 함께 적는다.

## 브랜드와 에셋

- 실제 `brand.md`와 디자인 가이드가 있으면 읽고 문체·색상값·로고 여백·서체·슬로건의 출처를 연결한다. 브랜드 가이드가 없으면 그 사실을 명시하고 기획은 계속한다. 임시 색·서체·문체는 제작 제안으로 구분하며 다른 브랜드의 가이드를 가져오거나 공식 규정으로 꾸미지 않는다.
- 새 캠페인 문구와 공식 슬로건을 구분한다. 로고 원본과 규격을 확보하지 못했으면 확인 항목으로 남기고 임의 제작을 지시하지 않는다. 브랜드 정보가 없는 상황을 모든 상품에 로고 승인을 요구하는 상시 절차로 확대하지 않는다.
- 에셋 기록의 상품 일치, 실제 내용과 사용 권한을 확인한다. 링크만 있는 자료를 보유 파일로, 정지 이미지를 실제 주행·조작 시연으로, 예시 UI 숫자를 제품 성능으로 쓰지 않는다. 상업적 재사용 권한과 다운로드 가능 여부는 별개다.
- 인용·후기와 시연의 원래 조건을 보존한다. 협찬·판매 관계를 숨기거나 비교 조건이 다른 자료로 성능·가격·내구성 순위를 만들지 않는다. 필요한 조건과 미확인 사항은 제작자가 알아볼 수 있게 적고, 일반적인 경고 목록을 불필요하게 늘리지 않는다.

## 저장과 수정

- 기본 경로는 `01-strategy/brief/<브랜드명>/<상품명>/`이다. 메시지 제안은 `marketing_messages.md`, 상세 브리프는 `brief.md`에 저장한다. 사용자 지정 경로와 기존 파일을 우선한다.
- 메시지 문서에는 후보별 고객·구매 이유·근거·한 줄 문구와 중요한 적용 조건을 둔다. 브리프에는 메시지별 채널과 행동의 요약, 콘텐츠 흐름, 제작 지시, 참고 출처와 확인할 항목을 둔다. 실제로 필요한 내용에 맞게 표와 문단을 사용한다.
- 한국어 작성과 교정은 사용자가 요청했거나 문서 작성에 적합한 경우 [natural-korean](../natural-korean/SKILL.md)을 읽고 적용한다. 문체를 고치면서 확정 메시지·수치·고유명사·직접 인용의 의미를 바꾸지 않는다.
- 피드백을 받으면 현재 메시지·브리프와 근거를 먼저 읽고 사용자 편집을 보존한다. 문구 수정은 필요한 부분만 고치고, 구매 이유·모델·고객·채널·근거가 바뀌면 메시지 요약, 콘텐츠 흐름, CTA와 제작 가이드까지 함께 수정한다. 가벼운 문구 변경 때문에 재수집하거나 기존 상품·경쟁·고객 문서를 덮어쓰지 않는다.
- 메시지 변경이 승인된 경우 두 문서의 대응 문구를 맞춘다. 브리프만 수정하는 요청에서 메시지 제안 원본을 임의로 바꾸지 않는다. 외부 사실을 갱신했을 때만 해당 확인일을 바꾸며 문서 작성일로 기존 조사일을 대체하지 않는다.

## 완료 확인

요청 수와 항목, 구매 이유의 차이, 메시지 원문 유지 여부, 주장과 근거의 연결, 모델과 조건, 브랜드 규정과 제안의 구분, CTA 목적지와 로컬 출처 링크를 확인한다. 최종 응답에는 파일 링크와 주요 방향, 제작에 영향을 주는 미확인 사항을 짧게 적는다.

## 산출물 생성 후 GitHub Push

산출물을 새로 만들거나 수정하고 검증을 마치면 [산출물 GitHub Push 절차](../../../docs/guides/skill-output-git-push.md)를 읽고 따른다. 이번 작업의 산출물과 필요한 관련 파일만 커밋한 뒤 GitHub 작업 브랜치로 push하고, 원격 반영을 확인한 후 완료를 보고한다. 별도 push 승인을 반복해서 묻지 않는다. 파일 변경이 없는 탐색·제안만 수행했다면 빈 커밋을 만들지 않는다.

## 성공 후 완료 알림

요청 범위의 검증과 필요한 GitHub push를 마치면 [공통 완료 알림](../notify-results/SKILL.md)을 읽고 카카오톡 나에게 보내기, 슬랙과 SenderKit 이메일로 핵심 결과와 산출물 링크를 보낸다. 실패하거나 push가 끝나지 않았으면 성공 알림을 보내지 않으며 하위 스킬로 실행한 경우 최상위 작업에서 한 번만 보낸다. 최종 답변에 채널별 전송 상태를 함께 알린다.
