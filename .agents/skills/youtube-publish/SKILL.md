# YouTube 콘텐츠 발행

영상과 기획서로 초안을 만들고 사용자가 승인한 원본과 메타데이터를 연결된 채널에 업로드한다. 초안과 실제 결과는 같은 발행 기록에 남긴다.

## 작업 기준

- 프로젝트의 `AGENTS.md`와 채널 관리 가이드를 읽고 `03-operation/channels/youtube/`에서 운영 자료를 관리한다.
- 기본 공개 범위는 비공개다. 사용자가 공개 또는 일부 공개를 지정하면 그 범위를 따른다.
- 승인은 영상, 대상 채널, 제목, 설명과 공개 범위에 적용한다. 이전 영상의 승인이나 스킬 호출 자체를 새 업로드 승인으로 간주하지 않는다.
- 확정된 초안을 사용자가 업로드하라고 지시했으면 같은 승인을 다시 묻지 않는다. 가장 최근의 공개 범위 지시를 따른다.
- 기존 영상의 수정 요청은 해당 변경의 승인으로 처리한다. 설명 수정에 재업로드나 공개 범위 변경을 포함하지 않는다.
- 인증 정보, 토큰, 인증 코드와 업로드 세션 URL을 출력하거나 발행 기록에 넣지 않는다.

## 영상과 기획서 확인

1. 지정한 콘텐츠 폴더와 영상을 찾는다. 영상이 여러 개이고 대상을 특정할 근거가 없으면 후보를 보여 주고 선택받는다.
2. 사용자가 기획서 경로를 지정했으면 그 문서를 우선한다. 폴더명이나 영상 길이만으로 기획서를 확정하지 않는다.
3. 관련 브랜드 자료, 상품 자료와 브리프를 읽고 문안의 근거를 정리한다. 없는 공식 지침이나 제원을 만들어 내지 않는다.
4. 원본 경로, 크기와 SHA-256을 기록하고 가능하면 길이와 해상도도 확인한다. 업로드 전 해시가 달라지면 기존 승인을 그대로 적용하지 않는다.
5. 영상 확인에는 이용 가능한 `watch` 스킬의 현재 지침을 따른다. 외부 서비스에 영상을 전송하는 과정이 있으면 먼저 설명한다.

분석이 실패하면 기획서의 설정을 실제 영상에서 확인한 사실로 쓰지 않는다. 해당 스킬의 재시도와 대체 처리 제한을 지키고 기획서 기반 초안에는 미확인 범위를 명시한다. 파일명만으로 AI 영상이라고 단정하지 않는다.

## 초안과 승인

- [발행 기록 양식](assets/publish-template.md)을 사용해 `publish-YYYYMMDD-N.md`를 작성한다. 한국 시간 날짜와 사용하지 않은 다음 번호를 쓰며 기존 기록은 덮어쓰지 않는다.
- 영상 미리보기 링크, 대상 채널, 제목과 설명 전문, 공개 범위를 함께 보여 준다.
- 제목은 100자 이내, 설명은 5,000자 이내로 작성한다. 브랜드 말투와 기획 의도를 반영하되 가격, 성능, 실제 시승 경험이나 공식 광고 여부를 지어내지 않는다.
- 아동용 여부와 사실적인 합성 콘텐츠 여부 등 필요한 설정도 근거에 따라 정한다.
- 초안 승인 전에는 업로드 API를 호출하지 않는다. 승인 내용과 시각, 사용자가 변경한 공개 범위를 기록한다.

## 인증과 업로드

실제 API 작업 전 [인증과 API 작업](references/youtube-api.md)을 읽는다.

1. 연결한 OAuth 계정으로 채널을 조회하고 승인한 채널과 일치하는지 확인한다.
2. 기존 발행 기록의 영상 ID와 저장된 업로드 세션부터 확인해 중복 생성을 피한다.
3. 승인한 원본 해시와 메타데이터를 확인하고 재개 가능한 업로드를 사용한다. 공개 범위를 명시적으로 전달한다.
4. 전송 완료 후 영상 ID와 링크를 즉시 기록하고 처리 중 상태와 처리 완료를 구분한다.
5. API로 채널, 제목, 설명, 실제 공개 범위와 처리 결과를 재조회한다. 요청한 범위가 적용되지 않았으면 완료라고 보고하지 않는다.
6. 최초 초안 파일에 결과와 확인 시각을 갱신하고 영상 링크를 사용자에게 알려 준다.

응답을 잃었다고 새 `videos.insert`부터 재실행하지 않는다. 마지막 확인 상태를 기록하고 같은 세션이나 발급된 영상 ID로 확인한다. 세션을 재개할 수 없어 새 업로드가 필요하면 그 사실을 사용자에게 설명한다.

## 발행 후 수정

- 기존 영상 ID로 현재 정보를 읽고 요청한 부분만 수정한다.
- 시간 언급은 `00:11`처럼 요청한 시점을 정확히 유지하고 확인하지 않은 장면 설명을 덧붙이지 않는다.
- 제목과 설명 수정에는 공개 범위, 아동용 설정, 합성 표시, 댓글과 원본 변경을 포함하지 않는다.
- 기존 메타데이터를 보존해 업데이트하고 API로 재확인한다. 발행 기록의 설명 전문과 수정 이력도 갱신한다.

## 완료 보고

영상 링크, 실제 공개 범위, 확인한 처리 상태와 발행 기록 파일을 짧게 보고한다. 실패하거나 처리 중인 상태는 그대로 알린다.

스킬 작성이나 수정은 실제 업로드를 허가하는 요청이 아니다. Git 커밋과 push는 프로젝트 규칙과 요청 범위에 따라 판단하며 비밀 파일이나 원본 영상을 임의로 포함하지 않는다.
