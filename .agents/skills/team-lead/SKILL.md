# Team Lead

독립적인 작업을 여러 에이전트에게 나눠 맡깁니다.

## 모델 설정

팀장은 작업 배분과 결과 확인을 맡고 작업자는 정해진 범위의 결과물을 만듭니다.
각 칸은 모델 / effort이며 Gemini에서는 effort 대신 `thinkingLevel`을 씁니다.

| 도구   | 팀장                              | 기본값                        | 코드 작업                         | 마케팅 조사                    | 마케팅 분석                       | 콘텐츠 생성                    |
| ------ | --------------------------------- | ----------------------------- | --------------------------------- | ------------------------------ | --------------------------------- | ------------------------------ |
| Codex  | `gpt-6.1-sol` / `high`            | `gpt-6.1-terra` / `low`       | `gpt-6.1-sol` / `high`            | `gpt-6.1-terra` / `low`        | `gpt-6.1-sol` / `high`            | `gpt-6.1-terra` / `medium`     |
| Claude | `claude-opus-5-5` / `xhigh`       | `claude-sonnet-5-5` / `low`   | `claude-opus-5-5` / `xhigh`       | `claude-sonnet-5-5` / `medium` | `claude-opus-5-5` / `high`        | `claude-sonnet-5-5` / `medium` |
| Gemini | `gemini-4-argon` / `high` | `gemini-3.8-flash` / `low` | `gemini-4-argon` / `high` | `gemini-3.8-flash` / `medium` | `gemini-4-argon` / `high` | `gemini-3.8-flash` / `medium` |

팀장은 업무 유형에 맞춰 작업자 설정을 고르고 어느 유형에도 맞지 않으면 기본값을 쓰거나, 적합한 모델과 Effort를 선택합니다.
팀장 설정은 사용자가 세션에서 고르고 작업자 설정은 팀장이 실행 옵션으로 전달합니다.
지원하지 않는 설정은 적용할 수 없다고 알립니다.

## 진행 순서

1. 사용자의 목표와 완료 기준을 정리합니다.
2. 담당 파일이나 산출물이 겹치지 않게 나누고 작업자에게 목표, 범위, 완료 기준과 필요한 자료를 전달합니다.
3. 독립적인 작업은 동시에 실행하고 선행 결과가 필요한 작업은 그 결과를 받은 뒤 시작합니다.
4. 일정이 바뀌거나 작업이 막히면 완료한 일, 남은 일과 예상 완료 시각을 짧게 알립니다.
5. 답을 기다리는 작업만 멈추고 나머지는 계속 진행합니다.
6. 실제 결과물과 검사 결과를 원래 요청과 대조한 뒤 합칩니다.
7. 결과, 확인한 내용과 남은 문제를 보고합니다.

## 작업 범위

- 프로젝트 규칙과 담당 범위를 지키고 사용자가 한 변경은 되돌리지 않습니다.
- 코드 변경이 충돌할 수 있으면 작업 폴더를 분리합니다.
- 무거운 검사는 팀장이 실행 순서를 조정합니다.
- 외부 게시와 배포는 사용자가 허락한 범위에서만 진행합니다.
- 하위 에이전트 도구가 없으면 그 사실과 혼자 수행할 수 있는 범위를 알립니다.
