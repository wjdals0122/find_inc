# 제품과 레퍼런스를 조합한 연출 컷

레퍼런스에서는 구도·조명·배경·분위기를 가져오고, 상품의 형태와 식별 요소는 제품 자료에서 유지한다. 자동차 외에도 패션, 화장품, 식품, 가전 등 실제 참고 이미지를 가진 상품에 적용한다.

## 자료와 작업 범위

- 대화와 프로젝트에서 브랜드·상품, 출력 건수·비율·해상도, 신규 수집/기존 자료 조합/피드백 수정 중 필요한 범위를 확인한다. 이미 답한 내용을 다시 묻지 않는다. 수집만 요청하면 생성까지 진행하지 않는다.
- 기본 탐색 위치는 아래와 같다. 사용자 지정 경로와 프로젝트 규칙을 우선한다.
  - 제품 원본: `01-strategy/brand/<브랜드명>/<상품명>/assets/`
  - 마케팅 브리프: `01-strategy/brief/<브랜드명>/<상품명>/brief.md`
  - 제품 컷·레퍼런스·결과: `02-contents/assets/<브랜드명>/<상품명>/`
- 실제 파일과 수집 기록을 먼저 확인한다. `product-shot1.png`처럼 그리드인 자료는 각 칸의 각도·디테일을 식별한다. 이전 피드백으로 수정된 버전이 있으면 사용자 지정 원본과 함께 읽고 어느 부분에 수정본을 적용할지 기록한다. 최신 파일이라는 이유만으로 지정 원본을 무시하지 않는다.
- 제품과 후보 이미지를 직접 열어 형태·색·재질·라벨·구성품을 확인한다. 브리프의 강조점, 금지 표현, 검증되지 않은 기능을 구분한다. 상품이 특정되지 않거나 핵심 외형 자료가 없으면 필요한 정보만 질문한다.
- 제품 컷 P개와 레퍼런스 R개의 전체 조합은 P×R개다. “NxN”만으로 생성 수나 결과의 그리드 배치를 확정하지 않는다. 건수가 크게 달라질 때는 대표 조합/레퍼런스별/전체 조합 중 범위를 확인하고 답변 전에는 자료 조사·조합안 작성만 진행한다. 총수가 이미 정해졌으면 다시 묻지 않는다.

## 레퍼런스 수집

웹 수집에는 사용 가능한 `crawler` 스킬을 찾아 읽고 예산·출처·원본 보존 지침을 적용한다. 없으면 아래 필수 기준으로 웹 검색과 직접 다운로드를 진행한다. 도구가 없다고 수집한 척하지 않는다.

- 기존 이미지와 URL·사진 ID를 대조한다. 신규 수집과 기존 재사용 건수를 구별한다. Pexels 등 지정 사이트를 우선하고 부족하면 다른 출처도 검토한다. 유료 수집은 승인된 예산 범위에서만 한다.
- 제품의 비율·소재·사용 상황과 브리프에 맞는 구도·빛을 고른다. 전체 모습, 측면, 디테일 등 역할을 다양하게 하되 확인하지 못한 실내·작동부·UI·효과를 채우려고 다른 상품의 구조를 가져오지 않는다.
- 검색 썸네일만으로 선정하지 않는다. 원본 페이지와 내려받은 사진을 확인하고 저해상도·중복·부적합 후보를 제외한다. 링크 표시 주소와 실제 연결 주소가 다르면 확인한다. 사용자가 둘 다 요청하면 서로 다른 이미지인지 검사해 각각 저장한다.
- 가능한 원본 해상도로 내려받아 실제 PNG로 저장한다. 확장자만 바꾸지 않는다. 제품 디테일용 자료와 분위기만 참고할 타 모델·타 브랜드 자료를 구별한다.
- `visual-reference1.png`부터 기존 번호 다음 빈 번호를 사용하고 덮어쓰지 않는다. 사진별 원문·이미지 URL, 사진 ID, 작가, 수집 시각(시간대 포함), 크기, 선정 이유, 사용할 요소, 차이점, 확인한 이용 조건을 기록한다. 내려받기 가능 여부를 상업적 사용 허가로 해석하지 않는다.

## 조합과 이미지 생성

- 사용 가능한 `imagegen` 스킬의 현재 지침을 읽고 내장 이미지 도구를 사용한다. 모델·크기 제어 때문에 CLI/API로 임의 전환하지 않는다. 도구가 없거나 실패하면 대안과 필요한 조건을 설명한다.
- 생성 전에 결과별 번호, 제품 파일과 그리드 칸, 레퍼런스 파일, 적용할 구도·빛·배경을 조합표로 정한다. 대표 조합은 비슷한 컷의 반복보다 브리프에 맞는 역할 분담을 우선한다. 개별 사진과 모아보기 그리드를 혼동하지 않는다.
- 입력마다 역할을 명시한다. 제품은 형태·색·재질·라벨·구성의 기준, 사용자 수정 참조는 지정 부위의 우선 기준, 연출 레퍼런스는 배경·조명·구도의 기준이다. 도구가 지원하는 방식으로 직접 확인한 이미지 입력을 전달한다.
- 레퍼런스의 상품·브랜드·문구·번호판·워터마크를 복제하지 않는다. 우리 제품의 로고·라벨은 사용자 요청과 제품 자료에 따라 유지한다. 참고 브랜드 금지를 이유로 우리 제품의 식별 요소까지 삭제하지 않는다. 별도 요청이 없으면 광고 문구나 인물을 추가하지 않는다.
- 요청 비율·품질·해상도를 프롬프트에 넣고 개별 연출 컷을 별도 이미지로 생성한다. 최고 모델·해상도는 실제 도구 범위에서 요청하며, 선택 옵션이 없으면 특정 모델 또는 4K 생성 완료라고 단정하지 않는다.
- `product-shot2.png` 형식을 따르되 기존 파일을 조사해 다음 빈 번호부터 저장한다. 파일 번호로 결과를 식별하고, 이미지 내부 숫자는 별도 요청이 있을 때만 넣는다. 수정본은 같은 번호의 `-v2`, `-v3`로 보존한다.
- 도구 기본 저장소의 결과를 프로젝트 폴더로 복사하고 출력 형식·실제 크기·비율을 검사한다. 비율이 다르면 도구에 정확한 비율로 한 차례 수정 요청하고, 여전히 다르면 실제 비율과 한계를 알린다. 단순 확대를 네이티브 고해상도 생성으로 보고하지 않는다.

## 결과 리뷰와 피드백 수정

최초 산출물 검토와 사용자 피드백이 도착했을 때 [리뷰 절차](references/review.md)를 적용한다. 파일·버전별로 지적 사항, 유지 조건, 수정 내용과 검증 결과를 연결한다. 내부 검토만으로 사용자 승인 처리하지 않는다.

## 저장 기록과 전달

- 배치마다 조합표·전체 프롬프트·참조 경로·실제 크기·생성 방식·검토 결과를 JSON 등 읽을 수 있는 기록으로 남긴다. 인증 정보와 이미지 base64는 제외한다. 같은 날짜의 기록도 덮어쓰지 않도록 배치 번호나 시각을 붙인다.
- 필요하면 파일 번호가 보이는 작은 모아보기를 만든다. 미리보기용 축소·배치는 원본 결과를 변경하지 않는 파일 처리이며 제품 외형·배경을 만드는 편집은 이미지 도구에서 한다.
- 최종 답변에는 실제 생성/수집 건수, 번호 범위, 저장 경로·미리보기·프롬프트 기록, 실제 크기와 제한, 피드백 반영 사항을 간결하게 알린다. 요청 없이 공개·배포·원격 업로드하지 않는다. 명시적인 프로젝트 저장·push 규칙이 적용되면 따른다.
