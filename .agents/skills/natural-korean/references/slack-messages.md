# 슬랙 메시지 작성 기준

브리핑, 리포트 보고, 진행 보고, 완료 알림과 오류 알림을 포함해 슬랙으로 보내는 모든 메시지에 적용한다. 스킬별 예시가 이 기준과 다르면 이 기준을 따른다.

## 문장과 구성

- 보내기 전에 [한국어 글쓰기 절차](writing-procedure.md)를 적용하고 최종 문장을 처음부터 끝까지 읽는다.
- 결론부터 친절하고 자연스럽게 설명한다. 독자가 판단하거나 행동하는 데 필요한 내용만 남긴다.
- 날짜가 있는 브리핑 제목은 `업무 브리핑 👩🏻‍💻 10월 22일`처럼 업무명, 이모지, 날짜 순서로 쓴다. 연도를 구분해야 하는 날짜에는 연도도 적는다.
- 본문 날짜는 `11/20`처럼 쓰고 시각이 확인됐으면 `11/20 23:00`처럼 24시간제로 적는다. 연도가 필요하면 `2027/01/31`처럼 쓰며, 확인하지 못한 마감 시각은 만들지 않는다.
- 가운데점과 불필요한 건수 안내를 쓰지 않는다. 판단에 필요한 금액, 기한과 오류 수치는 유지한다.
- 짧은 알림은 한두 문장으로 끝낸다. 긴 메시지는 제목, 소제목과 하위 내용을 구분하고 절 사이에 여백을 둔다.
- 파일 이름에는 열 수 있는 직접 링크를 건다. 게시하지 않은 파일의 원격 주소를 만들거나 로컬 경로를 코드 표시로 대신하지 않는다.

| 메시지 | 제목 형식 |
| --- | --- |
| AI 소식 | `AI 소식 🤖 10월 22일` |
| 지원사업 조사 | `지원사업 조사 🏦 10월 22일` |
| 업무 브리핑 | `업무 브리핑 👩🏻‍💻 10월 22일` |
| 재무 브리핑 | `재무 브리핑 💰 10월 22일` |

## 슬랙 서식

전송 방식의 서식을 확인한다. 본문은 Slack이 권장하는 `rich_text`를 우선 사용하고 굵게, 인용과 링크를 요소의 속성으로 지정한다. 별표 바로 뒤에 한글 조사가 붙는 `*금액*입니다` 같은 mrkdwn은 별표가 그대로 보일 수 있으므로 쓰지 않는다. Incoming Webhook의 `mrkdwn`은 일반 Markdown과 다르며 API의 `markdown_text`나 `markdown` 블록과 문법을 섞지 않는다.

| 용도 | Incoming Webhook과 mrkdwn |
| --- | --- |
| 제목 | Block Kit `header`의 `plain_text`를 쓴다. |
| 소제목 | 굵은 글씨의 글머리표로 표시하고 `rich_text_list`의 `indent`를 `0`으로 지정한다. |
| 하위 내용 | 소제목 아래의 글머리표로 구성하고 `rich_text_list`의 `indent`를 `1`로 지정해 한 단계만 들여쓴다. |
| 강조 | rich text 요소에 `style: {"bold": true}`를 지정한다. |
| 링크 | rich text의 `link` 요소에 `url`과 `text`를 넣는다. mrkdwn에서는 `<https://example.com/report|전체 리포트>`처럼 이름을 붙인다. |
| 마감 기한 | 기한 라벨만 rich text의 별도 `text` 요소로 나누고 `style: {"code": true}`를 지정한다. mrkdwn에서는 `` `~11/30 13:00` ``이나 `` `상시 지원` ``처럼 쓴다. |
| 인용 | 원문을 직접 인용할 때만 `rich_text_quote`를 쓴다. mrkdwn에서는 `>`로 시작한다. |
| 구분선 | 다른 메시지와 구분하도록 메시지 맨 아래에 Block Kit `divider` 하나만 넣고 본문 중간에는 넣지 않는다. |
| 목록 | `rich_text_list`의 `style`을 `bullet`로 지정하며 공백 문자나 글머리 기호를 직접 붙여 들여쓰기를 흉내 내지 않는다. |
| 코드 | 명령어, 코드와 로그에만 코드 블록을 쓴다. 설명과 파일 링크는 코드 블록에 넣지 않는다. |
| 표 | 본문에 Markdown 표를 붙이지 않고 짧은 목록이나 지원되는 Block Kit 표로 바꾼다. |

- 제목에는 글머리표를 붙이지 않는다.
- 모든 슬랙 보고는 제목 아래에 별도 요약문을 두지 않고 첫 소제목이나 본문부터 시작한다.
- `요약`, `한 줄 요약`, `핵심 요약` 부제와 요약용 `rich_text_quote` 블록을 쓰지 않는다.
- 소제목을 쓸 때는 상위 글머리표로 표시하고, 그 아래 내용과 관련 링크는 한 단계 들여쓴 하위 글머리표로 정리한다.
- 마감 기한은 설명 문장과 분리해 라벨만 인라인 코드 서식으로 표시한다. 문장 전체나 링크에는 코드 서식을 적용하지 않는다.
- 이 문서는 메시지의 내용, 분류, 소제목 이름과 순서, 항목 수를 정하지 않는다. 작성자는 실제 내용에 맞춰 자유롭게 구성한다.
- 인용 블록은 출처의 원문을 직접 인용해야 할 때만 쓴다. 나머지 본문은 하위 글머리표로 쓴다.
- Block Kit 메시지는 `--payload-file`로 보낸다. `text`에는 알림과 접근성을 위한 대체 텍스트를, `blocks`에는 실제 본문을 넣는다. 대체 텍스트를 별도 본문 블록으로 반복하지 않는다.
- 서식이 보인다는 추측으로 검수를 끝내지 않는다. payload와 실제 슬랙 표시를 확인하고, 화면을 확인하지 못했다면 그 한계를 남긴다.
- 기존 메시지를 수정할 때는 실제 작성자 ID가 토큰의 사용자나 봇 ID와 일치하는지 확인한다. 같은 앱에 속한 웹훅과 봇도 작성자 ID가 다르면 수정할 수 없다.
- Incoming Webhook만으로 수정했다고 보고하지 않는다. 기존 글을 삭제하거나 교정본을 추가하려면 사용자가 선택한 방법을 따른다.
