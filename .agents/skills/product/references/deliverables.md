# 상품 문서와 수집 기록

## 폴더

기존 구조가 없으면 다음을 사용한다. 실제 내용이 없는 디렉터리·파일은 만들지 않는다.

```text
01-strategy/brand/<상품명>/
  product.md
  assets/
    <확인한 이미지·설명서·관련 파일>
    sources.json
  collection/
    manifest.json
    records.jsonl
    failures.jsonl
    excerpts.json
```

상품명이 모호해 구분이 필요하면 모델·세대·버전을 폴더 이름에 포함한다. 파일명에 공백·한글이 있어도 유지할 수 있다. 현재 프로젝트 밖에서 사용자가 별도 산출물 경로를 정하면 그 경로를 따른다.

## product.md의 권장 구성

사용자가 지정한 형식이 있으면 우선하고, 아래는 실제 상품에 맞춰 합치거나 줄인다.

1. **대상과 확인 범위:** 브랜드·정확한 상품명·모델/버전·국가·확인일, 출시·판매 상태, 제외한 유사 상품.
2. **기본 정보:** 스펙·기능·옵션·구성품·사용법·호환/설치 조건. 공식 확정값·잠정값·후기 관측을 구분한다.
3. **가격:** 조건별 가격표, 정가/할인/월 납입액 구분, 미확인 비용과 가격 적용일.
4. **사용 조건:** 소모품·정비·운영비, 보증·서비스 범위, 구독 갱신·해지·환불.
5. **사용 후기:** 실제 사용 근거별 장점·아쉬움과 환경·기간. 소비자 장기 사용·전문 단기 사용·정차/매장 체험을 나눈다. 영상 미시청과 후기 부재도 명시한다.
6. **주요 장점과 근거:** 사용자 이점·근거 수준·적용 한계.
7. **미확인 및 사이트별 조사 상태:** 실패와 미실행을 구분하고 후속 확인에 필요한 자료를 적는다.
8. **에셋·출처·수집 기록:** 실제 파일과 근거 목록으로 연결한다.

### 가격표 필드

`시장 | 모델·버전 | 옵션·구성 | 가격·통화 | 가격 종류 | 세금·배송·설치/계약 조건 | 확인일 | 직접 출처`

가격 유효 기간이 있으면 별도로 적는다. 옵션을 확인하지 못한 상태로 모델 기본가격과 임의로 합산하지 않는다. 해외 가격은 원화 환산보다 원통화·시장 구분을 우선하고, 환산을 요청받으면 환율·시점을 표시한다. 단위나 시험 규격이 다른 수치를 같은 값으로 취급하지 않는다.

### 장점 표 필드

`특징 | 사용자 이점 | 근거와 출처 | 확인 수준·조건·한계`

장점이 공식 설명뿐이면 ‘제조사 주장’으로 표시한다. 단기 체험의 감상을 검증된 신뢰성·장기 내구성으로 확대하지 않는다. 상반된 경험이 있으면 감추지 않는다.

## collection 기록

crawler가 있으면 그 `references/records.md`를 따른다. 원본을 전문으로 보관할 수 없으면 짧은 발췌와 직접 출처·위치를 저장한다. 문서 내용과 기록 사이에 불필요한 원문 복제를 만들지 않는다.

- `manifest.json`: 조사 대상·기간·언어·지역·범위, 예산 상한·통화, 확인 비용·미확인 비용·진행 중 비용, 도구별 실행 내역, 신규/재사용/부분/실패/미실행 집계.
- `records.jsonl`: 안정적인 ID, 대상 식별 조건, 유형, 원래/정규 URL, 제목·언어, 게시일·수집 시각·검증 시각, 도구·실행 ID, 원문 파일/발췌 참조, 근거 위치, 재사용 출처, 상태와 제한. 후기에는 사용 기간·환경·관계(구매자/기자/협찬 등)를 가능한 범위에서 남긴다.
- `excerpts.json`: 원어 발췌·영상 자막/발언·OCR 등 종류를 구분하고 번역·요약과 별도 보존. 정확한 원문이 없으면 null과 사유를 기록한다.
- `failures.jsonl`: URL·시도 시각·도구·실행 ID·실제 오류·누락 범위·재시도 횟수·다음에 필요한 조건. 미시도는 실패와 구별한다.

댓글·답글에는 `root_post_id`, `root_post_url`, `parent_id`, 자신의 ID/직접 링크를 보존한다. 페이지네이션·정렬·필터·실제 수집 수·남은 자료 여부를 기록한다. 부모가 안 보이면 null을 쓴다.

영상은 원본 기준 시작/끝 시각, 타임스탬프 링크, 분석 구간, 원문 인용·화면 글·Gemini 관찰·번역을 구분한다. Gemini 보고서 자체가 발언의 축어록은 아니다.

시각은 ISO 8601 오프셋을 포함한다. 기록 작성 시각과 도구 실행 시각이 다르면 각각 적는다. 과거의 정확한 시각이 없으면 null과 알려진 날짜/정밀도를 기록한다.

## assets/sources.json

각 파일에 다음을 남긴다.

`filename`, `asset_url`, `source_page`, `subject/model`, `collected_at`, `format`, `bytes`, 가능하면 `sha256`, `visual_checked`, `description`, `rights`, `limitations`.

이미지·PDF 텍스트 확인 시 페이지 번호·원본 크기·구간 번호·좌표·OCR·판독 불가 영역도 추가한다. 형식을 파일 확장자만 보고 판단하지 않는다. 확인용 캡처·편집본을 만들면 원본과 파생 관계를 기록한다. 권리 확인 전에는 ‘자유 사용’으로 표시하지 않는다.

## 수정 시 기록

- 사용자가 확정한 대상·조사 범위 정정을 반영하고, 근거가 바뀐 사실에만 검증일을 갱신한다.
- 내용 변경이 있는 원문은 버전을 구분하고 이전 기록 ID를 남긴다. 기존 수집 시각을 덮어쓰지 않는다.
- 정정으로 제외된 자료·에셋은 이유를 기록한다. 참조가 남아 있는 파일을 임의로 삭제하지 않는다.
- 최종 답변에는 변경 파일과 중요한 변경·누락만 간단히 설명한다. 본문에 불필요한 대화 경과를 누적하지 않는다.
