# Product

상품의 구매·사용·마케팅 판단에 필요한 근거 문서를 만든다. 실물 상품뿐 아니라 소프트웨어, 구독, 서비스에도 적용한다. 사이트 탐색, 수집, 문서 작성, 후속 수정 중 사용자가 요청한 범위를 수행한다.

## 요청 범위와 상품 식별

- 대화와 기존 파일에서 브랜드·상품명·공식 URL·모델·세대·버전·연식·지역·대상 고객, 예산과 저장 위치를 확인한다. `rg`로 기존 조사와 에셋을 찾아 활용한다.
- 공식 링크의 상품 식별을 먼저 확인한다. 같은 상품명이 다른 세대나 버전을 가리키면 차이를 설명한다. 문맥상 명확한 브랜드 오기는 해석을 밝히고 진행하되, 서로 다른 상품 중 하나를 임의로 고르지 않는다.
- 세대·버전·국내외 사양이 다른 자료를 섞지 않는다. 사용자가 대상을 정정하면 그 정정을 기준으로 범위를 갱신한다. 기존 자료는 일치 여부를 검토해 재사용하거나 제외한다.
- 사용자가 **사이트만 찾아 달라 / 아직 수집하지 말라**고 하면 주소·대상 일치 여부를 확인하는 최소 검색만 한다. 본문 추출, 댓글 수집, 영상 분석, 이미지 다운로드 및 상품 문서 작성은 시작하지 않는다. 탐색 결과에 사이트별 직접 주소·조사 항목·접근 상태를 간단한 표로 제시하고 그 범위에서 마친다.
- 사용자가 수집·정리를 요청하면 이미 지정한 조사 범위와 예산으로 실행한다. 탐색에서 수집으로 넘어가는 상시 승인 단계를 새로 만들지 않는다. 예산·권한처럼 실제로 필요한 정보만 묻고 독립적으로 가능한 작업은 계속한다.

## 사이트 탐색

| 목적 | 우선 조사처와 판단 기준 |
|---|---|
| 공식 정보 | 제조사·서비스 제공자 상품 페이지, 설명서·카탈로그, 공식 가격표·견적 구성기, 이용약관·보증·고객지원 |
| 실물 상품 스펙·가격 | **다나와와 네이버 쇼핑을 필수 확인 채널**로 포함한다. 해당 상품 전용 페이지를 찾고 다른 모델·세대·용품·모형·중고·렌탈 상품과 구분한다. 자동차 등은 전문 카테고리도 사용한다. |
| 소프트웨어·구독·서비스 | 공식 요금제·기능 비교·제공 지역·약관·해지/환불 정책. 실물용 채널을 억지로 적용하지 않는다. |
| 실사용 후기 | 국내외 판매처의 구매자 후기, 전문 커뮤니티, 유튜브·블로그. 실구매·소유·단기 시승·정차 체험·협찬·단순 반응을 구별할 수 있는 출처를 선택한다. |

- 직접 주소를 찾지 못하면 검색 진입 주소임을 밝힌다. 검색 결과에 나오는 다른 버전의 페이지를 정확한 상품 페이지처럼 제시하지 않는다.
- 필수 채널의 접근 제한·미등록·본문 미확보는 조사 상태에 남긴다. 검색 실패로 ‘판매 안 함’이나 ‘후기 없음’을 단정하지 않는다. 원문에 해당 모델의 후기 0건이 명시된 경우에만 그 페이지의 확인 결과로 기록한다.
- 외국 가격·후기는 국내 정보의 대체재가 아니라 시장별 보완 근거로 쓴다.

## 자료 수집

실제 수집 시 사용 가능한 [crawler 스킬](../crawler/SKILL.md)을 읽고 적용한다. 상품별 조사 항목과 결과 문서의 구성은 이 스킬이 맡고, 수집·저장·예산의 세부 절차는 crawler를 따른다. crawler가 없으면 아래 핵심 조건으로 가능한 무료 조사를 진행하고 누락된 기능을 알린다. 존재하지 않는 도구·스킬을 설치된 것처럼 말하지 않는다.

- 웹검색과 **Bright Data**로 원문을 찾고, 게시물·댓글도 Bright Data를 우선한다. 부족한 채널·필드는 **Apify**로 보완한다. 사용자가 특정 도구를 정하면 그 선택을 우선한다. 도구 스키마와 가격을 확인하고 실행 ID 및 실제 출력까지 검증한다. 검색 설명·빈 데이터·실행 성공 상태만으로 원문 수집 완료를 선언하지 않는다.
- 영상은 설치된 **watch의 Gemini 엔진**으로 말과 필요한 화면을 분석한다. `--engine gemini --no-whisper`를 사용하고 원문 인용·번역·관찰·요약, 원본 영상의 시작/끝 시각을 나눠 보존한다. 자막만으로 화면을 판단하거나 제목·설명을 시청 근거로 쓰지 않는다. 엔진 실패 시 다른 엔진으로 자동 전환하지 않는다.
- 상품 이미지·PDF 표·각주도 직접 확인한다. 긴 이미지는 겹치는 구간으로 나누고 원본 위치를 기록한다. OCR 결과의 숫자·단위·행열을 시각 대조한다. 못 읽은 구간은 미확인으로 남긴다.
- 기존 승인 예산·유료 실행 금지 조건을 유지한다. 다른 세션의 특정 금액을 모든 상품의 기본값으로 만들지 않는다. 예산이 없으면 유료 호출 전에 상한을 확인하고 무료 조사는 계속한다. 진행 중 비용과 재시도까지 포함해 상한을 지키며, 상한을 임의로 제거하지 않는다.
- 동일 원문·재게시·기존 자료는 중복 집계하지 않는다. 댓글·답글에는 자신의 ID, 원글 ID·주소, 바로 위 부모 ID를 남긴다. 관계가 안 보이면 추측하지 않는다.
- 원문과 요약, 출처·위치, 게시일·수집 시각·검증 시각, 사용 도구, 누락 범위를 구별해 보존한다. 정확한 과거 수집 시각이 없으면 미확인으로 남기고 이번 저장 시각을 과거 시각으로 대체하지 않는다.

## 조사 항목

상품에 필요한 항목을 골라 조사하되 요청된 핵심 항목은 빠뜨리지 않는다. 해당 없음과 미확인은 구분한다.

1. **기본 정보:** 용도·사용자, 모델/버전, 스펙, 기능, 옵션, 포함·별도 구매 구성품, 설치·호환 조건, 사용법. 설명서가 없으면 소개 문구로 상세 안전 절차를 재구성하지 않는다.
2. **가격:** 모델·연식/버전·옵션·구성·국가·통화·세금/배송·설치·확인 날짜와 출처를 묶는다. 정가·할인가·개인 거래가·리스 월 납입액·구독료를 구별한다. 가격 적용일과 확인일도 구분한다. 정확한 옵션이 없으면 해당 모델의 확정 총가격으로 단정하지 않는다.
3. **사용 조건:** 소모품·교체 주기·관리비, 보증 기간/거리·제외 항목, 수리·지원 범위, 구독 무료 기간·자동 갱신·해지·환불·지역 제한. 일반 브랜드 정책과 해당 모델 계약상 보장을 구분한다. 구독이 없으면 해지는 해당 없음이고, 존재 여부나 약관을 못 확인했으면 미확인이다.
4. **실사용 후기:** 장점·아쉬움·발생 조건, 기간, 사용 모델·환경, 후기 성격. 전문가의 실제 사용도 근거로 쓸 수 있지만 소비자 장기 소유로 바꾸지 않는다. 불만 사례를 일반 결함·발생률로 단정하지 않는다.
5. **주요 장점:** 특징 → 사용자에게 주는 이점 → 출처·측정/관찰 → 적용 조건·한계를 연결한다. 제조사 설명, 실측, 단일 체험, 여러 후기의 반복 경향을 구분한다. 비교·보장 근거 없이 ‘최고’, ‘완벽’, ‘비용 절감 보장’을 만들지 않는다.

## 결과 문서와 에셋

작성 단계에서 [문서와 기록 형식](references/deliverables.md)을 읽는다.

- 지정 위치가 없으면 `01-strategy/brand/<상품명>/product.md`와 같은 폴더의 `assets/`에 정리한다. 사용자 지정 경로·기존 폴더를 우선한다. 경로에 쓸 수 없는 문자만 안전하게 치환하고 임의의 다른 상품명 폴더를 만들지 않는다.
- 출처를 각 주장·표 가까이에 둔다. 가격 행에는 반드시 모델·옵션 조건·확인 날짜를 남긴다. 상충 정보는 지역·조건·시점을 대조하고 해소되지 않으면 병기한다.
- 요청한 이미지는 실제로 다운로드하고 파일을 열어 상품·버전과 형식을 확인한다. 이미지 안의 예시 숫자를 실측값으로 쓰지 않는다. 에셋별 원본 URL·출처 페이지·수집 시각·파일명·확인 상태·재사용 권한을 기록한다. 링크만 저장했으면 다운로드 완료라고 말하지 않는다.
- 원본·발췌·관측과 문서의 해석을 분리한다. 저작권·개인정보·플랫폼 조건에 따라 보존 가능한 범위만 저장하고 전문을 못 보존하면 그 이유를 밝힌다. 상업적 재사용 허가는 다운로드 가능 여부와 별개다.

## 피드백에 따른 수정

- 사용자의 새 메시지가 상태 질문이면 완료·남은 항목·막힌 이유를 짧게 답하고 작업을 계속한다. 범위·모델·예산 정정이면 그 조건을 반영해 기존 목표를 이어간다. 중단 요청은 따른다.
- 수정 전에 현재 `product.md`, 관련 기록·에셋을 읽고 다른 사용자의 편집을 보존한다. 필요한 부분을 직접 수정하며 문서를 불필요하게 새로 만들지 않는다.
- 모델/세대 변경 시 제원·가격·후기·사용 조건·이미지를 모두 대상과 재대조한다. 기존 파일을 무단 삭제하거나 다른 세대 정보를 복사해 채우지 않는다. 제외 사유와 이전 기록 위치를 남긴다.
- 문구 수정은 재수집 없이 처리할 수 있다. 새 사실·가격 갱신은 필요한 출처만 재확인한다. 실제로 확인한 항목의 날짜만 바꾸고, 원래 수집 시각·원문 버전은 유지한다.
- 근거가 틀렸다는 피드백을 받으면 요약뿐 아니라 원문 기록, 표, 주요 장점, 이미지 설명 등 파생 항목까지 함께 수정한다. 미확인 항목이 확인되면 출처·확인일을 추가한 뒤 상태를 바꾼다.

## 완료 확인과 보고

- 요청 항목, 모델/지역 구분, 가격 조건·날짜, 주장별 출처, 실제 후기의 성격, 미확인/해당 없음 표시를 확인한다. 로컬 문서·이미지 링크를 열고 JSON 등의 기록을 파싱해 깨진 참조와 가짜 다운로드를 확인한다.
- 결과 파일 링크, 주요 확인 내용, 중요한 미확인·실패, 수집/재사용/부분 수집 건수와 실제 비용·미확인 비용을 짧게 보고한다. 실패를 감추거나 확인 범위를 넘어 완료를 선언하지 않는다.
- 산출물의 GitHub push는 아래 절차에 따라 수행한다. 웹 게시·서비스 배포나 자동 다중 에이전트 작업은 요구하지 않는다. 사용자가 병렬 작업을 요청한 경우에만 해당 협업 지침을 적용하고 담당 범위를 나눈다.

## 산출물 생성 후 GitHub Push

산출물을 새로 만들거나 수정하고 검증을 마치면 [산출물 GitHub Push 절차](../../../docs/guides/skill-output-git-push.md)를 읽고 따른다. 이번 작업의 산출물과 필요한 관련 파일만 커밋한 뒤 GitHub 작업 브랜치로 push하고, 원격 반영을 확인한 후 완료를 보고한다. 별도 push 승인을 반복해서 묻지 않는다. 파일 변경이 없는 탐색·제안만 수행했다면 빈 커밋을 만들지 않는다.
