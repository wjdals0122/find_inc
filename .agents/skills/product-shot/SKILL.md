# 제품 연출 컷 제작

브랜드·상품에 맞는 기준 그리드를 만든 뒤, 그 안의 각도·디테일을 연출 레퍼런스와 조합한다. 자동차뿐 아니라 화장품·식품·패션·가전 등 제품 사진이 있는 상품에 적용한다. 한 단계만 요청받으면 그 범위를 존중한다.

## 연결할 스킬

아래 지침을 실행할 단계에서 읽고 실제 작업에 적용한다. 이름만 언급하고 절차를 생략하지 않는다.

1. [product-shot-grid](../product-shot-grid/SKILL.md): 기준 제품 그리드 생성·검토.
2. [product-shot-reference](../product-shot-reference/SKILL.md): 레퍼런스 수집·개별 연출 컷 생성·피드백 리뷰.

각 스킬이 사용하는 `imagegen`, `crawler` 지침도 해당 단계에서 읽는다. 의존 스킬이 없으면 프로젝트와 현재 스킬 목록에서 찾고, 그래도 없으면 누락된 경로와 가능한 작업 범위를 알린다. 다른 도구로 실행한 것을 해당 스킬 실행으로 보고하지 않는다.

## 시작과 자료 확인

- 대화와 프로젝트에서 브랜드·상품, 원본·브리프, 기존 생성물·수집 기록·피드백을 확인한다. 확인된 정보와 승인된 작업 범위는 다시 묻지 않는다. 상품명을 BMW 등 특정 사례로 고정하지 않는다.
- 기본 자료 위치는 `01-strategy/brand/<브랜드명>/<상품명>/assets/`, `01-strategy/brief/<브랜드명>/<상품명>/brief.md`이고, 결과 위치는 `02-contents/assets/<브랜드명>/<상품명>/`이다. 사용자 경로와 프로젝트 규칙을 우선한다.
- 실제 제품 사진을 열어 외형·색·재질·라벨·구성품과 버전을 구분한다. 브리프가 없으면 그 사실을 밝히고 확보한 자료 범위에서 진행한다. 핵심 제품 이미지가 없거나 다른 상품들이 섞여 대상을 특정할 수 없을 때만 필요한 자료를 묻는다.
- 기존 결과를 이어서 작업할 때는 어느 단계까지 끝났는지 확인한다. 현재 상품·조건·피드백에 맞는 그리드가 있으면 1단계에서 재사용 검토를 수행한 뒤 2단계로 이어간다. 사용자가 새로 만들라고 하지 않았는데 생성 비용을 들여 처음부터 반복하지 않는다.

## 1단계: 제품 그리드

- `product-shot-grid`를 적용한다. 기본은 간격을 최소화한 **3×3 그리드 한 장, 세로 9:16**이다. 상품 종류에 맞게 전체 모습·측면·후면·핵심 디테일을 구성하고 사용자 지정 배치·비율을 우선한다.
- 배경은 제품색·확인된 브랜드 컬러·브리프에 맞춘다. 공식 색상 규격이 없으면 제작 제안으로 구분한다. 실제 사진에 없는 기능·UI·부품을 확정 사양처럼 만들지 않는다.
- 결과를 원본과 비교해 모든 칸의 제품 식별 요소를 점검한다. 제품 외형에 중대한 오류가 있으면 해당 부위를 수정한 뒤 조합 단계에 넘긴다. 해결되지 않은 오류를 후속 컷 전체에 복제하지 않는다. 생성 그리드는 각도 참조이며 제품 사실의 최종 근거는 원본이다.
- 사용자가 “앞부분은 이 사진처럼” 등 수정 참조를 주면 그 부위를 우선 기준으로 적용한다. 색·구도·배경·다른 칸은 요청 범위 밖에서 유지한다. 수정본과 기존본을 함께 보존하고 후속 작업에서 사용할 파일·부위·우선순위를 기록한다.
- 새 프로젝트는 `product-shot1.png`, 기존 파일이 있으면 `product-shot1-v2.png` 같은 새 버전으로 저장한다. 사용자가 명시하지 않은 덮어쓰기를 하지 않는다.

## 단계 연결

그리드 파일·버전, 행/열별 제품 각도·디테일, 적용한 피드백, 유지할 외형·색·라벨, 원본과의 차이·미확인 사항을 짧은 조합 기록에 남긴다. 기준을 충족하면 별도 승인 질문 없이 2단계로 진행한다. 사용자가 중간 확인을 요청했다면 그 지시를 따른다.

## 2단계: 레퍼런스와 조합

- `product-shot-reference`를 적용한다. 기존 `visual-reference` 파일을 먼저 확인하고, 필요한 연출은 Pexels 등 요청 사이트에서 찾아 저장한다. 신규와 재사용을 구별하고 원문 출처·작가·수집 시각·원본 크기·선정 이유·확인한 이용 조건을 보존한다. 유료 수집에는 해당 스킬의 예산 지침을 따른다.
- 제품 컷 P개와 레퍼런스 R개를 전부 조합하면 P×R개다. “NxN”만으로 전체 수나 그리드 납품을 결정하지 않는다. 이미 정해진 수량을 따르고, 해석에 따라 작업량이 크게 달라지면 대표 조합/레퍼런스별/전체 조합 중 범위를 확인한다. 예전의 대표 9장 선택을 모든 상품의 필수 수량으로 고정하지 않는다.
- 결과마다 제품 칸·기준 버전·레퍼런스·적용할 구도와 빛을 매핑한다. 레퍼런스에서는 구도·분위기를, 제품 자료에서는 외형을 가져온다. 참고 상품의 브랜드·문구·구조를 복제하지 않고 우리 제품의 실제 식별 요소는 보존한다.
- 요청된 수의 **독립된 연출 이미지**를 만든다. 별도 지정이 없으면 세로 9:16을 사용한다. 그리드 한 장이나 모아보기를 개별 결과 여러 장으로 세지 않는다.
- `visual-reference<N>.png`와 `product-shot<N>.png`는 기존 번호를 조사해 다음 빈 번호에 저장한다. 새 프로젝트의 개별 컷은 `product-shot2.png`부터 시작한다. 수정본은 같은 번호에 `-v2`, `-v3`를 붙인다. 이미지 내부 번호는 따로 요청받았을 때만 넣는다.

## 사용자 피드백과 최종 전달

- [공통 리뷰 절차](../product-shot-reference/references/review.md)를 그리드와 개별 컷 모두에 적용한다. 피드백을 **바꿀 것 / 유지할 것 / 확인 기준**으로 정리하고 대상 파일·버전에 연결한다. 반복 생성 횟수와 중단 기준도 그 절차를 따른다.
- 기준 제품의 수정은 영향을 받는 후속 컷에만 적용한다. 배경에 대한 피드백으로 제품 모양을 바꾸거나 특정 부위 수정 때문에 모든 컷을 다시 만들지 않는다. 기존 승인된 부분이 망가지지 않았는지 전후 비교한다. 감사·호응을 최종 승인이나 공개 허가로 확대하지 않는다.
- 최고 모델·최대 해상도 요청은 사용 가능한 도구 범위에서 실행한다. 모델·크기 선택 옵션이 없으면 임의로 CLI/API로 바꾸거나 4K 완료라고 말하지 않는다. 실제 PNG 크기·비율을 검사하고 불일치는 각 하위 스킬의 재시도 기준에 따라 처리한 뒤 남은 한계를 보고한다.
- 그리드·개별 컷의 프롬프트, 입력 파일·그리드 칸·레퍼런스 연결, 실제 크기, 버전, 리뷰·미해결 사항을 배치별 기록에 남긴다. 상품 폴더에 원본 결과를 저장하고 번호가 보이는 모아보기와 클릭 가능한 파일·폴더 경로를 함께 제공한다. 링크가 안 열리면 확인된 로컬 경로와 탐색기에서 찾는 방법을 안내하며 웹 다운로드 링크라고 부르지 않는다.
- 최종 답변에 그리드 수와 개별 컷 수를 나눠 보고하고, 수집/재사용 건수·번호 범위·실제 크기·제약·피드백 반영 내용을 간결하게 전달한다. 이 스킬 실행은 공개·배포·push까지 자동 승인하는 것이 아니다. 명시된 프로젝트 규칙과 사용자 요청 범위에 따른다.
